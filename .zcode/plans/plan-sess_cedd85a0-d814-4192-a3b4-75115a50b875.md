# Plan: Auth-System & Seeder komplett entfernen

## Ziel
Die App braucht kein eigenes Login mehr. Schutz erfolgt rein über die Infrastruktur (Reverse Proxy / VPN / nur-interner Zugriff) — „ein Guard weiter vorne, nicht auf App-Ebene". Deshalb wird **die gesamte Session-basierte Authentifizierung und der Seeder** entfernt.

## Vorentscheidungen (nach deinem Wortlaut)
- **Seeder komplett weg** — inkl. Demo-Daten (Kategorien/Rezepte). Die DB startet leer; Kategorien/Rezepte legst du selbst an (oder per KI).
- **APIs ungeschützt auf App-Ebene** — `hooks.server.ts` enthält danach keinen Auth-Check mehr. Schreib-APIs (POST/PUT/DELETE) sind ohne App-Schutz; Sicherheit liegt beim Reverse Proxy.

## Vorgehen — 7 Blöcke

### Block 1: DB-Migration (Flyway V4)
**Neu:** `db/migration/V4__drop_auth.sql`
```sql
DROP TABLE IF EXISTS sessions;
DROP TABLE IF EXISTS users;
```
(V1 wird nicht angerührt — Flyway checksummt. `sessions` hat keinen FK zu `users`, Reihenfolge unkritisch.) V1/V2/V3 bleiben unverändert. Beim nächsten `up migrator` wird V4 eingespielt.

### Block 2: Server-Seite aufräumen
- **`src/hooks.server.ts`** → stark vereinfachen: nur noch Seed/DB-Initialisierung enfernen, kein Auth mehr. Resultat: `export const handle: Handle = ({ event, resolve }) => resolve(event);` (oder Datei löschen, falls sonst nichts drin ist).
- **`src/lib/server/db.ts`** → die 7 Auth-Funktionen entfernen (`createSession`, `validateSession`, `deleteSession`, `cleanupExpiredSessions`, `getUserByUsername`, `createUser`, `deleteUser`, Zeilen 63–114) plus Sektionskommentar. Pool + Date-Helper bleiben.
- **`src/lib/server/session.ts`** → **löschen** (ganze Datei, nur dünner Wrapper).
- **`src/lib/server/seed.ts`** → **löschen** (ganze Datei — CATEGORIES, RECIPES, RECIPE_VARIANTS, seedUser, seedIfEmpty).
- Importe/Calls in `hooks.server.ts` entfernen (`seedIfEmpty`, `seedUser`, `validateSession`, `cleanupExpiredSessions`).

### Block 3: Auth-API & Login-Route löschen
- **`src/routes/api/auth/`** → gesamtes Verzeichnis löschen (login, logout, verify).
- **`src/routes/login/`** → gesamtes Verzeichnis löschen (`+page.svelte`).
- **`src/lib/auth.svelte.ts`** → **löschen** (Client-Auth-State).

### Block 4: Routes, die verifySession importieren (editieren, nicht löschen)
Zwei Routes haben zusätzlich zum Hook noch einen eigenen `verifySession`-Check — der fällt weg:
- **`src/routes/api/categories/[id]/+server.ts`** → Import entfernen (L4), Guards bei PUT (L13–16) und DELETE (L39–42) entfernen.
- **`src/routes/api/recipes/[id]/favorite/+server.ts`** → Import entfernen (L4), Guard bei POST (L12–15) entfernen.

### Block 5: UI — Auth-Gates entfernen (immer anzeigen)
Da „immer eingeloggt" gilt, werden alle `{#if auth.isLoggedIn}`-Wrappers aufgelöst (Inhalt immer rendern), Imports entfernt:
- **`src/lib/components/NavDrawer.svelte`** — Import (L5) + `refreshAuth` (L13–16) weg; 3 Gates auflösen: `/chat`-Link (L44–52) und `/settings`-Link (L73–77) **immer** zeigen; Login/Logout-Block (L78–86) **komplett löschen**.
- **`src/lib/components/ImageUpload.svelte`** — Import (L2) weg; Upload-Gate (L49–65) auflösen → immer Upload zeigen, den „als Admin einloggen"-Hint (L60–64) löschen; 401-String (L31) anpassen.
- **`src/lib/components/RecipeCard.svelte`** — Import (L3) weg; Favoriten-Stern (L58–67) immer zeigen.
- **`src/routes/recipe/[id]/+page.svelte`** — Import (L11) weg; 3 Gates auflösen: Bild-Upload (L138, L145) immer zeigen, KI-Button (L199) immer zeigen.

### Block 6: Dependencies & Env-Variablen
- **`package.json`** → `bcryptjs` (dep) + `@types/bcryptjs` (devDep) entfernen (nur von `seed.ts`/`api/auth/login` genutzt). `pnpm install` zum Aktualisieren.
- **`.env`** → `ADMIN_USERNAME`, `ADMIN_PASSWORD` entfernen.
- **`.env.example`** → ADMIN_*-Block entfernen (DB_* und IMAGES_DIR bleiben).

### Block 7: Doku (CLAUDE.md, README.md)
- Auth-Beschreibungen, Session/`ADMIN_PASSWORD`-Hinweise, Login-Endpunkte aus Doku entfernen.
- Neuen Infra-Schutz-Hinweis ergänzen („App ist ungeschützt, nur Reverse Proxy schützt").
- Seeder-Abschnitt in CLAUDE.md streichen.
- `users`/`sessions` aus dem Datenmodell-Teil entfernen, V4 erwähnen.
- `.env.example`/Env-Tabellen aktualisieren.
